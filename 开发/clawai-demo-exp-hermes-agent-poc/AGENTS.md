# 项目级 Agent 约定

## 项目定位

本项目是一个面向制造咨询场景的 AI 应用，当前首个 Demo 场景为“在线一次校验合格率管控”。

## 工作原则

- 优先保护“可信数字”：数据口径来自语义层，结论来自规则引擎，模型只负责解释与成文。
- 前端只消费结构化报告协议，不在前端编写业务判断和指标计算逻辑。
- OpenClaw 只负责工具编排、模型路由、提示词装配和 Hook 注入，不直接访问数据库。
- 所有关键链路都应携带 `traceId`，并具备审计记录。

## 代码与文档约定

- 设计文档统一放在 `docs/architecture/` 下，按“导航、场景、总体设计、实施计划、AI资产”分类。
- 与场景强相关的设计优先写中文文件名，便于业务和研发共同阅读。
- 协议优先沉淀到 `packages/`，避免接口定义散落在各服务目录。
- 新增目录或文件前，先考虑是否已有现成分类可以承接。

## 工程实现约定

- `apps/bff`：任务入口、鉴权、审计透传、OpenClaw 调用适配。
- `services/semantic-api`：受控查询、指标定义、字段映射、查询审计。
- `services/playbook-engine`：规则、阈值、判断树、结构化结论。
- `services/openclaw-runtime`：Skill、工具白名单、模型路由、Prompt 模板。
- `services/report-service`：结构化报告装配与落库。
- `apps/web`：向导页、任务页、报告页、统一渲染器。

## 变更优先级

1. 先让链路跑通
2. 再替换 mock 为真实能力
3. 最后优化并发、缓存、审计和体验
