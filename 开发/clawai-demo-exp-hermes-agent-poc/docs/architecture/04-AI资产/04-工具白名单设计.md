# 1. 工具白名单设计

## 1.1 目标

控制 OpenClaw 可调用的工具范围，确保模型不会自由发现数据源或绕过业务边界。

## 1.2 设计原则

- 白名单按分析技能分组
- 工具输入输出必须使用受控协议
- 工具只暴露必要能力，不做通用代理
- 每次工具调用都必须写审计日志

## 1.3 当前场景首批工具

当前已落地到插件目录：

- `plugins/openclaw-domain-tools`

当前首个 demo 场景实际启用的首批工具为：

- `query_fpyr_daily`
- `query_defect_item_breakdown`
- `query_equipment_event_timeline`
- `run_quality_playbook`
- `build_quality_report`

对应固定技能：

- `quality_first_pass_yield`（`first_pass_yield_monitoring`）

第二技能（趋势简报）白名单子集：

- `query_fpyr_daily`
- `run_quality_playbook`
- `build_quality_report`

对应技能：

- `quality_fpyr_trend_brief`（`first_pass_yield_trend_brief`）

当前已实现的分支策略：

- 主导异常类别为 `磁物类`：优先走设备关联线索路径
- 主导异常类别为 `ICP类`：优先走来料/工艺路径，设备线索可后置
- 其他类别：走通用平衡路径

## 1.4 工具元信息建议

每个工具建议至少定义：

- `toolKey`
- `skillKey`
- 输入协议
- 输出协议
- 调用后端服务
- 超时配置
- 审计等级
- 失败后的降级策略

## 1.5 边界要求

- 工具不能接收原始 SQL
- 工具不能暴露任意 HTTP 请求能力
- 工具不能绕过语义层直接访问数据库
- 工具不能让模型自行决定数据口径
