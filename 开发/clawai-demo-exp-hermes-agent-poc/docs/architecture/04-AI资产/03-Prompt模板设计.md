# 1. Prompt 模板设计

## 1.1 目标

把模型提示词从零散代码中抽离出来，形成可维护、可版本化、可审计的 Prompt 体系。

## 1.2 分层建议

- 系统 Prompt：定义角色、边界、禁止事项
- 场景 Prompt：定义当前分析场景的目标和输出风格
- 步骤 Prompt：定义单个步骤的输入、输出和格式要求
- 模板变量：注入事实数据、规则结论、模板版本、审计上下文

## 1.3 当前场景建议

对于“在线一次校验合格率管控”，Prompt 应坚持以下原则：

- 只能依据给定事实解释，不允许编造数据
- 不允许修改规则引擎结论
- 输出要适合品质专员和品管经理阅读
- 保持报告语言专业、简洁、可追溯

## 1.4 推荐变量

- `analysisType`
- `traceId`
- 指标摘要
- 异常分布
- 原料/设备关联事实
- 规则引擎输出
- 报告模板版本
- 输出风格要求

## 1.5 版本管理建议

- Prompt 模板要有版本号
- 重要变更要记录变更原因
- 报告中可记录所使用的 Prompt 模板版本，便于追溯
