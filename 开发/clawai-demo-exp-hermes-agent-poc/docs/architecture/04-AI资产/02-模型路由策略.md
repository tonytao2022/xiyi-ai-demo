# 1. 模型路由策略

## 1.1 目标

明确不同场景、不同步骤使用什么模型，以及何时不用模型，避免所有请求都走同一模型。

## 1.2 路由原则

- 查数、规则判断优先不用模型。
- 模型只负责解释、成文、归纳，不负责编造数字和业务口径。
- 模型选择应由 OpenClaw 控制，不由前端或用户直接指定。
- 复杂场景可升级更强模型，普通场景优先用成本更低的模型。

## 1.3 当前场景建议

### 1.3.1 `first_pass_yield_monitoring`

- 语义层查询：不用模型
- 规则引擎判断：不用模型
- 报告解释和成文：调用默认解释模型
- 遇到长上下文或复杂异常归因：升级更强模型
- 模型失败时：降级为规则模板文案

## 1.4 路由输入

OpenClaw 做模型路由时，建议参考以下维度：

- `analysisType`
- `skillKey`
- 当前步骤
- 事实数据量
- 上下文长度
- 是否需要高阶解释
- 成本与并发预算

## 1.5 审计要求

每次模型调用至少记录：

- `traceId`
- `analysisType`
- `skillKey`
- `stepKey`
- `modelKey`
- 输入摘要
- 输出摘要
- 耗时
- 是否发生降级
