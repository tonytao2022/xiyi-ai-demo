# 目录骨架建议

## 目标

以最小单体仓目录先承接架构决策，再逐步工程化为可运行的多包仓。

## 建议目录

```text
        reporting/

```

## 各目录用途

- `apps/web`：客户入口、分析向导、任务页、报告页。
- `apps/bff`：鉴权、租户隔离、任务触发、报告查询、审计透传。
- `services/openclaw-runtime`：OpenClaw 网关接入、工具注册、Hook 适配。
- `services/semantic-api`：指标查询、模板查询、数据口径与血缘输出。
- `services/playbook-engine`：方法论、阈值、规则判断、诊断解释。
- `services/report-service`：结构化报告装配、导出适配、报告存取。
- `packages/analysis-contract`：分析任务输入协议。
- `packages/metric-contract`：受控指标查询协议。
- `packages/report-schema`：统一报告协议与区块定义。
- `plugins/openclaw-domain-tools`：白名单工具定义与领域服务适配器。
- `scripts/sql/mysql`：首个 demo 的 `MySQL 8.0` 建库建表与初始化脚本。
- `docs/architecture/00-导航`：目录导航、阅读顺序、文件作用说明。
- `docs/architecture/01-场景`：业务场景定义文档。
- `docs/architecture/02-总体设计`：系统边界、安全、目录骨架等总体设计文档。
- `docs/architecture/03-实施计划`：端到端计划和开发计划。
- `docs/architecture/04-AI资产`：Agent、规则、Prompt、模型路由、工具白名单等 AI 资产说明。

## 初始化顺序

1. 先固化 `packages/*` 协议，避免服务实现前接口漂移。
2. 再搭建 `apps/bff` 与 `services/*` 的最小 HTTP 骨架。
3. 然后接入 `plugins/openclaw-domain-tools`，把领域服务挂入 OpenClaw。
4. 最后落 `apps/web` 的统一报告渲染器与任务流页面。

## MVP 范围建议

- 首个 demo 固定为“在线一次校验合格率管控”。
- 首个分析技能建议固化为 `first_pass_yield_monitoring`。
- 只开放少量白名单工具，如指标查询、规则执行、报告生成。
- 报告区块先支持 `markdown`、`kpi_cards`、`table`、`chart`。
- 所有输出先对齐结构化报告 Schema，再扩展 PDF 导出和更多图表类型。

## 首个 Demo 落点

- 场景设计文档：`docs/architecture/01-场景/01-首个-demo-场景-在线一次校验合格率管控.md`
- 前端优先实现：该场景的分析向导、任务页、报告页
- 后端优先实现：一次校验合格率查询、异常分布分析、关联分析、报告生成
