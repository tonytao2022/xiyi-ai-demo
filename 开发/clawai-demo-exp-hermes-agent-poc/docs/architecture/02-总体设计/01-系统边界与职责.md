# 系统边界与责任

## 分层原则

- 客户只与 `Web` 交互，不直接访问模型运行时、领域服务或数据库。
- `BFF` 是唯一的应用入口，负责把用户意图转换为受控的分析任务。
- `OpenClaw` 只做智能编排，不拥有业务结论的最终裁量权。
- 可信数字来自 `语义层`，可信判断来自 `规则引擎`，可信交付来自 `报告服务`。

## 责任矩阵

| 模块 | 负责内容 | 明确不负责 |
| --- | --- | --- |
| Web | 场景入口、任务发起、任务状态、结构化报告展示、导出触发 | 自由对话、业务判断、拼装核心结论、直连 OpenClaw |
| BFF | 鉴权、租户隔离、参数校验、任务编排入口、审计透传、报告查询 | 指标计算、规则判断、直接执行数据库查询 |
| OpenClaw | 模型路由、Prompt 装配、Hook 注入、工具调用编排、失败重试 | 自主发现任意工具、定义业务口径、直接访问数据库 |
| 语义层 | 指标定义、维度映射、模板查询、数据血缘、查询审计 | 自由 SQL 执行、报告排版、自然语言成文 |
| 规则引擎 | 方法论、阈值、判断树、规则解释、诊断结论产出 | 绕过数据口径、渲染 UI、直接向客户暴露原始内部规则 |
| 报告服务 | 汇总规则结果与模型解释、输出统一报告 Schema、固化可回溯来源 | 发起分析任务、改写核心数字、嵌入前端展示逻辑 |

## 标准调用链

1. `Web` 提交分析向导参数给 `BFF`。
2. `BFF` 生成标准分析请求，补齐租户、用户、模板、`traceId` 等上下文。
3. `BFF` 调用 `OpenClaw` 的预设技能入口，不允许前端传自由 Tool 名称。
4. `OpenClaw` 只能通过白名单工具调用 `语义层`、`规则引擎`、`报告服务`。
5. `语义层` 返回带口径信息与审计 ID 的指标结果。
6. `规则引擎` 基于方法论生成定量和定性判断。
7. `报告服务` 统一组装结构化报告 JSON。
8. `BFF` 返回任务状态或报告实体给 `Web`，由前端按 Schema 渲染。

## 边界约束

- `Web -> BFF`：只传业务场景参数，不传模型指令或原始查询语句。
- `BFF -> OpenClaw`：只传模板化请求与技能标识，不传开放式工具权限。
- `OpenClaw -> 语义层`：只传受控指标查询对象，不传原始 SQL。
- `OpenClaw -> 规则引擎`：只传结构化事实，不传未审计的自由文本结论。
- `报告服务 -> Web`：只输出报告协议，不输出前端专用拼装逻辑。

## 模块间共享资产

- `packages/analysis-contract`：分析任务输入协议。
- `packages/metric-contract`：受控指标查询协议。
- `packages/report-schema`：报告协议与区块类型。
- `plugins/openclaw-domain-tools`：OpenClaw 白名单工具定义与适配层。

## 首个 Demo 场景映射

当前建议优先实现的首个 demo 为“在线一次校验合格率管控”，其目标是让品质专员或品管部经理围绕一次校验合格率做日常监控、异常定位和结构化报告输出。

### Web

- 提供该场景专用的分析向导、任务状态页和报告页。
- 输入范围限定为组织、工厂、时间范围、产品线、批次和分析关注点。
- 不暴露自由聊天窗口，也不允许用户手动拼接查询逻辑。

### BFF

- 接收前端的场景化输入，组装为 `first_pass_yield_monitoring` 分析请求。
- 统一补齐 `traceId`、租户上下文、用户身份、模板版本和技能标识。
- 把请求路由到该场景固定的 OpenClaw 技能，不允许开放式 Tool 指定。

### OpenClaw

- 以 `quality_first_pass_yield` 作为预设技能编排入口。
- 按白名单顺序协调指标查询、异常归因、规则执行和报告生成。
- 只负责流程编排和解释增强，不负责定义一次校验合格率口径。

### 语义层

- 提供一次校验合格率、不合格检验项目、批次、原料、ICP、粒度、设备事件等受控查询能力。
- 把 `MOM/MES` 数据映射为统一指标和维度，并返回口径版本、数据时间戳和查询审计 ID。
- 拒绝原始 SQL 与未注册指标访问。

### 规则引擎

- 固化该场景的诊断 Playbook，例如先识别异常检验项目，再选择原料、过程或设备关联路径。
- 基于阈值、判断树和方法论生成定量结论与建议动作。
- 输出的规则结论必须可回溯到事实输入和规则版本。

### 报告服务

- 输出该场景的结构化报告 JSON，包括 KPI 总览、异常分布、关联分析、结论与建议四类区块。
- 保留 `sourceRefs` 和 `auditTrail`，支撑前端展示与后续审计。
- 不改写规则层给出的核心定量结论，只负责装配和格式化。
