# 1. 首个 Demo 场景：在线一次校验合格率管控

## 1.1 场景定位

将“在线一次校验合格率管控”定义为制造咨询智能体的首个 demo 场景，用于验证整套架构是否能够在受控输入、多源数据关联、规则诊断和结构化报告输出之间形成闭环。

## 1.2 目标用户

- 品质专员
- 品管部经理

## 1.3 工作目标与业务价值

- 及时识别一次校验合格率的异常波动。
- 快速定位导致不合格的核心检验项目和可能原因。
- 串联原料、批次、配比、过程参数、设备维护等信息做关联判断。
- 输出结构化分析报告，支撑质量改进与管理决策。

## 1.4 工作频次与协作对象

- 工作频次：每日 / 每周
- 主要协作方：技术管理经理
- 输出去向：品质团队内部复盘、技术管理沟通、异常整改跟踪

## 1.5 数据输入与来源

### 1.5.1 关键输入

- 一次校验合格率数据
- 不合格批次与检验项目异常数据
- 物料制造过程数据
- 原料批次与原料配比
- 原料磁物数据
- ICP 数据
- 粒度等过程质量数据
- 设备维修、保养等设备状态数据

### 1.5.2 输入来源

- `MOM`
- `MES`

## 1.6 标准分析链路

1. 从 `MOM/MES` 抽取一次校验合格率及相关批次、检验项目数据。
2. 对不合格项目进行分类统计，识别异常占比最高的检验项目。
3. 按检验项目类别决定后续关联分析路径。
4. 若涉及 `ICP`、粒度等项目，则继续关联原料投批次、原料配比、原料磁物等数据。
5. 将设备维修、保养等设备状态信息纳入异常解释范围。
6. 由规则引擎形成诊断结论，由模型补充解释文字和报告表达。
7. 输出结构化报告供前端统一渲染。

## 1.7 系统实现映射

- `Web`：提供该场景的分析向导、任务状态和报告页，不提供自由聊天。
- `BFF`：把“在线一次校验合格率管控”场景输入转换为标准分析请求，补齐 `traceId`、租户和模板上下文。
- `OpenClaw`：按预设技能编排指标查询、规则执行和报告生成工具。
- `语义层`：负责一次校验合格率及相关维度的数据查询、字段映射和审计输出。
- `规则引擎`：负责异常识别、归因路径选择、阈值判断和结论模板。
- `报告服务`：统一生成结构化报告 JSON，供前端渲染与导出。

## 1.8 建议的首个分析技能

- `analysisType`: `first_pass_yield_monitoring`
- `skillKey`: `quality_first_pass_yield`
- `reportTemplateVersion`: `fpyr-demo-v1`
- `playbookVersion`: `quality-fpyr-v1`

## 1.9 受控输入建议

- `tenantId`
- `orgId`
- `siteId`
- `timeRange`
- `productLineId`
- `materialCode`
- `batchId`
- `analysisFocus`

其中 `analysisFocus` 可选值建议包括：

- `yield_overview`
- `defect_breakdown`
- `raw_material_correlation`
- `equipment_correlation`

## 1.12 MVP 范围

- 仅实现这一个 demo 场景，不同时展开多个制造咨询主题。
- 仅接入支持一次校验合格率分析所需的最小 `MOM/MES` 数据集。
- 仅支持固定白名单工具，不开放通用工具调用。
- 仅支持 `markdown`、`kpi_cards`、`table`、`chart`、`insight_list` 这几类报告区块。
- 仅输出结构化报告与 Web 报告页，导出能力可后置。

## 1.13 不做项

- 不做自由问答式质量分析助手。
- 不做模型直连数据库或自生成 SQL。
- 不做多场景通用工作台。
- 不在前端内嵌质量诊断规则或指标计算逻辑。

## 1.14 成功标准

- 能自动生成一次校验合格率异常分析报告。
- 能指出主要不合格检验项目及可追溯的数据来源。
- 能对原料、过程参数、设备事件给出结构化关联线索。
- 能让品质团队把分析工作从手工汇总切换为标准化任务流。
