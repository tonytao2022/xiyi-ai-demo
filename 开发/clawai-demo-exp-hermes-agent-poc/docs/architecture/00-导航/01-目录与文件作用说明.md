# 1. 目录与文件作用说明

## 1.1 目标

说明当前项目中各主要目录、核心文档和 AI 独立资产的作用，作为后续查找和维护的总入口。

## 1.2 文档区结构

### 1.2.1 `docs/architecture/00-导航/`

- 用于存放文档导航、目录说明、阅读顺序说明。
- 适合放“先看什么、每个目录干什么”的说明文档。

### 1.2.2 `docs/architecture/01-场景/`

- 用于存放业务场景定义文档。
- 回答“这个 Demo 做什么、给谁用、输入输出是什么”。

### 1.2.3 `docs/architecture/02-总体设计/`

- 用于存放系统边界、安全约束、目录骨架等总体设计文档。
- 回答“系统怎么分层、边界怎么划、基础结构怎么搭”。

### 1.2.4 `docs/architecture/03-实施计划/`

- 用于存放端到端计划和开发计划。
- 回答“按什么顺序做、每阶段交付什么、怎么验收”。

### 1.2.5 `docs/architecture/04-AI资产/`

- 用于存放模型路由、Prompt、工具白名单、Agent 约定等 AI 专有资产说明。
- 回答“模型怎么选、Prompt 怎么管、工具怎么控、规则写在哪里”。

### 1.2.6 `docs/data/`

- 用于存放数据源、指标口径、字段映射、语义层指标字典等数据设计文档。
- 回答“有哪些指标、指标怎么定义、从哪些表来、输出什么字段”。
- 当前建议先平铺维护，等数据文档数量增多后再拆一级分类。

## 1.3 核心目录结构

### 1.3.1 `apps/`

- 存放面向用户的应用入口。
- 当前包括：
  - `apps/web`：前端 Web 应用（含 `README.md` 说明页路由与渲染原则）
  - `apps/bff`：后端 BFF 应用

### 1.3.2 `services/`

- 存放领域服务和智能运行时。
- 当前包括：
  - `services/semantic-api`：语义层
  - `services/playbook-engine`：规则引擎
  - `services/report-service`：报告服务
  - `services/openclaw-runtime`：OpenClaw 运行时

### 1.3.3 `packages/`

- 存放共享协议和基础契约。
- 当前包括：
  - `analysis-contract`
  - `metric-contract`
  - `report-schema`

### 1.3.4 `plugins/`

- 存放 OpenClaw 白名单工具和插件适配层。

### 1.3.5 `scripts/sql/mysql/`

- 存放首个 demo 的 `MySQL 8.0` 初始化脚本。
- 适合沉淀 `MES` 模拟库与应用库的建库建表 SQL。

### 1.3.6 `.cursor/rules/`

- 存放 Cursor 的持久规则文件。
- 作用是让 AI 在编辑和阅读特定文件时自动带上相应约定。

### 1.3.7 `AGENTS.md`

- 存放项目级 Agent 约定。
- 作用是告诉 AI 和开发者：这个项目是什么、核心原则是什么、长期约定是什么。

### 1.3.8 `docs/data/`

- 存放与数据库、字段、指标和口径直接相关的文档。
- 适合沉淀语义层 `metricKey` 定义、数据映射和样例输出。
- 当前已包括：
  - 语义层指标草案
  - 来源表与字段映射草案
  - 指标计算与查询逻辑草案
  - 样例查询输入输出
  - 业务确认清单
  - 检验项目字典与分类映射
  - 数据库初始化方案

## 1.4 当前建议阅读顺序

1. `README.md`
2. `docs/architecture/00-导航/01-目录与文件作用说明.md`
3. `docs/architecture/01-场景/01-首个-demo-场景-在线一次校验合格率管控.md`
4. `docs/architecture/02-总体设计/` 下文档
5. `docs/architecture/03-实施计划/` 下文档
6. `docs/architecture/04-AI资产/` 下文档
7. `docs/data/` 下文档

## 1.5 什么时候把内容写到哪里

- 业务目标和场景边界：写到 `01-场景`
- 系统职责和设计约束：写到 `02-总体设计`
- 研发推进顺序和验收方式：写到 `03-实施计划`
- 模型、Prompt、工具、规则这类 AI 专属内容：写到 `04-AI资产`
- 指标、口径、表结构映射、语义层查询能力：写到 `docs/data/`
- 项目长期约定：写到 `AGENTS.md`
- 编辑器或 AI 需要自动感知的规则：写到 `.cursor/rules/`

### 1.6.1 备注（维护与阅读说明）

- 该结构树是“工作视图”，强调核心链路与主要文件，不等同于 `tree` 全量输出。
- `#` 后注释用于说明“职责重点”，帮助快速定位；若职责变化，请同步更新注释。
- 文档类目录（`docs/architecture`、`docs/data`）按“导航 → 场景 → 总体设计 → 实施计划 → AI资产 / 数据设计”阅读更高效。
- 新增功能时，优先复用现有目录；仅在确实无法承载时再新增一级目录。
- 新增关键文件后，建议在本节补一行，并在对应 `README` 或架构文档补充其输入/输出与边界。
- 若目录结构发生明显变化（重命名、迁移、拆分服务），应在同次变更中同步更新本节，避免文档失真。
