# 1. 首个 Demo 指标计算与查询逻辑草案

## 1.1 目标

整理“在线一次校验合格率管控”场景当前可识别的指标计算逻辑、查询路径和分析步骤，为语义层查询模板与规则引擎输入设计提供依据。

## 1.2 说明

- 本文档基于当前截图和已有场景说明整理，属于草案版。
- 当前重点是沉淀“理解到的业务计算思路”，不是最终 SQL 方案。
- 后续应结合真实数据库验证公式、条件和异常值口径。

## 1.3 核心业务目标

围绕“一次校验合格率”完成以下动作：

- 统计日/周一次校验合格率
- 找到不合格批次和不合格项目结构
- 判断是否存在混料影响
- 从工序投入产出链路追溯原料和过程因素
- 关联设备检修和异常时间点
- 输出结构化异常分析报告

## 1.4 当前可识别的计算逻辑

### 1.4.1 一次校验合格率主逻辑

当前已确认的业务口径为：

- 以入库或成品批次数作为基础总量
- 若某批次的性能判定结果为不合格，则该批次计入不合格
- 未判定批次从分母中排除
- 基于合格批次数与已判定总批次数计算一次校验合格率

建议先按以下思路抽象：

- `totalBatchCount = 指定时间范围内满足入库条件且已判定的批次总数`
- `qualifiedBatchCount = 指定时间范围内判定为合格的批次数`
- `defectBatchCount = 指定时间范围内判定为不合格的批次数`
- `fpyr = qualifiedBatchCount / totalBatchCount`

当前默认统计范围：

- 主统计表：`tsh_pro_stock_record`
- 过滤条件：`stock_oper_order = "ZKI"`
- 统计时间字段：`stock_chng_time`
- 批次唯一关联键：`mat_no`

### 1.4.2 不合格判定逻辑

当前已确认的信息为：

- 使用 `pch_judge_code`（性能判定结果）作为关键判定字段
- 判定值定义：
  - `N`：未判定
  - `S`：合格
  - `F`：不合格
  - `A`：内控合，规格不合
  - `B`：内控不合，规格合
- 当前已确认：
  - `S` 视为合格
  - `A/B/F` 视为不合格
  - `N` 从分母中排除

后续需进一步确认：

- 是否需要叠加 `complex_judge_code` 做综合判定
- 是否存在其他应排除的状态值

### 1.4.3 混料重量处理逻辑

当前截图可理解为：

- 如果批次在处置后物料信息表中能够匹配到 `mat_no_to`
- 则读取该批次对应的 `mix_wt`
- 若混料重量为空，则按 `0` 处理

该逻辑的用途可能包括：

- 作为异常批次的归因线索
- 在报告中展示“批次是否涉及混料”

当前默认判断：

- 混料重量不直接进入一次校验合格率主公式
- 混料信息主要用于原料/批次关联分析和原因解释

## 1.5 当前可识别的查询路径

### 1.5.1 总览查询路径

目标：统计一次校验合格率和不合格批次数。

建议路径：

1. 从 `tsh_pro_stock_record` 获取批次、库存变更时间
2. 按批次关联 `tdmmm` 获取性能判定结果
3. 识别：
   - 合格批次：`S`
   - 不合格批次：`A/B/F`
   - 排除批次：`N`
4. 按时间聚合计算：
   - `fpyr_daily`
   - `defect_batch_count`

### 1.5.2 不合格项目结构查询路径

目标：找出主要不合格项目或类别。

建议路径：

1. 从 `tdmmm` 获取不合格批次对应的 `entr_no`
2. 关联 `tqmtq_entrust_result`
3. 读取 `item_code`、`item_name`、`act_result_value`
4. 按项目名称或项目类别聚合输出：
   - `defect_item_breakdown`

### 1.5.3 原料/工序追溯查询路径

目标：找到异常批次可能涉及的原料、工序和投料记录。

建议路径：

1. 从工序产出表组定位异常批次所在工序和产出记录
2. 通过 `seq_no` 或批次链路关联工序投入表组
3. 获取 `real_mat_no`、`mat_code`、`mat_wt`、`feed_time`
4. 输出原料和工序线索，供规则引擎和报告服务使用

### 1.5.4 设备关联查询路径

目标：判断设备异常是否与合格率波动时间重合。

建议路径：

1. 从主表或趋势结果中确定异常时间段
2. 查询 `teq_repair_manage` 在该时间段内的设备故障和维修事件
3. 输出按时间排序的设备事件列表：
   - `equipment_event_timeline`

## 1.6 与首批 `metricKey` 的关系

### 1.6.1 `fpyr_daily`

- 目标：输出每日一次校验合格率
- 输入基础：批次 + 性能判定结果
- 用途：总览、趋势、异常识别

### 1.6.2 `defect_batch_count`

- 目标：输出不合格批次数量
- 输入基础：批次 + 判定结果
- 用途：异常规模评估

### 1.6.3 `defect_item_breakdown`

- 目标：输出不合格项目分布
- 输入基础：委托号 + 检验项目结果
- 用途：分析路径选择

### 1.6.4 `mix_weight_by_batch`

- 目标：输出批次对应混料重量
- 输入基础：批次号 + 混料信息
- 用途：混料影响识别

### 1.6.5 `equipment_event_timeline`

- 目标：输出设备故障/维修/保养时间线
- 输入基础：设备事件记录
- 用途：设备因素关联分析
