# 1. 数据设计阅读顺序

## 1.1 目标

说明 `docs/data/` 下各文档分别解决什么问题，以及建议的阅读顺序，帮助业务、研发和 AI 协作时快速建立共同理解。

## 1.2 当前文档列表

- `00-数据设计阅读顺序.md`
- `01-首个demo-语义层指标草案.md`
- `02-首个demo-来源表与字段映射草案.md`
- `03-首个demo-指标计算与查询逻辑草案.md`
- `04-首个demo-样例查询输入输出.md`
- `05-首个demo-业务确认清单.md`
- `06-首个demo-检验项目字典与分类映射.md`
- `07-首个demo-数据库初始化方案.md`

## 1.3 推荐阅读顺序

### 1.3.1 第一步：看指标定义

先看：

- `01-首个demo-语义层指标草案.md`

这份文档回答：

- 这个场景第一批要做哪些 `metricKey`
- 每个指标的业务含义是什么
- 每个指标大概给谁用

适合：

- 产品经理
- 业务同事
- 语义层开发
- 规则引擎开发

### 1.3.2 第二步：看来源表和字段

再看：

- `02-首个demo-来源表与字段映射草案.md`

这份文档回答：

- 指标主要从哪些表来
- 每张表的核心字段是什么
- 哪些字段是批次键、判定字段、时间字段
- 表之间大概怎么关联

适合：

- 数据开发
- 语义层开发
- 需要和业务确认表结构的人

若要做「不合格检验项目按磁物 / ICP / 粒度等类别」的聚合或模拟数据，紧接着建议阅读：

- `06-首个demo-检验项目字典与分类映射.md`

### 1.3.3 第三步：看计算与查询逻辑

然后看：

- `03-首个demo-指标计算与查询逻辑草案.md`

这份文档回答：

- 主指标怎么算
- 不合格怎么判定
- 为什么要查某些表
- 查询路径和分析链路是什么

适合：

- 语义层开发
- 规则引擎开发
- OpenClaw 工具设计

### 1.3.4 第四步：看样例输入输出

接着看：

- `04-首个demo-样例查询输入输出.md`

这份文档回答：

- `MetricQuery` 应该怎么传
- `MetricQueryResult` 应该怎么返回
- 前后端和规则引擎怎么消费这些结果

适合：

- BFF 开发
- 语义层开发
- 规则引擎开发
- 前端联调

### 1.3.5 第五步：业务确认清单（进入开发前）

在进入开发或联调前，建议业务与研发共同过一遍：

- `05-首个demo-业务确认清单.md`

### 1.3.6 第六步：数据库初始化与联调准备

进入真实库联调前，建议阅读：

- `07-首个demo-数据库初始化方案.md`

这份文档回答：

- 为什么建议拆成 `mes_demo` 与 `ce_agent_demo`
- 首版最小应先建哪些表
- `MySQL 8.0` 脚本的执行顺序是什么

## 1.4 文档之间的关系

可以按下面这条线理解：

1. `01` 定义“要查什么”
2. `02` 定义“从哪里查”
3. `06` 定义“检验项目字典与业务分类怎么映射”（依赖 `02` 中的委托结果与字典）
4. `03` 定义“怎么算、怎么串”
5. `04` 定义“接口长什么样”
6. `05` 在进入开发前核对业务口径与待确认项
7. `07` 定义“数据库怎么初始化、双库怎么拆”

## 1.5 推荐协作方式

### 1.5.1 和业务同事沟通时

优先使用：

- `01-首个demo-语义层指标草案.md`
- `03-首个demo-指标计算与查询逻辑草案.md`

因为业务更关心：

- 指标是什么意思
- 判定规则是什么
- demo 最终能看见什么

### 1.5.2 和数据/研发同事沟通时

优先使用：

- `02-首个demo-来源表与字段映射草案.md`
- `04-首个demo-样例查询输入输出.md`

因为研发更关心：

- 表怎么关联
- 字段怎么用
- 接口怎么传和怎么返回

## 1.6 后续维护建议

- 当业务口径确认后，优先更新 `01` 和 `03`
- 当表结构确认后，优先更新 `02`
- 当检验项目字典或分类口径变化时，优先更新 `06`
- 当接口格式调整后，优先更新 `04`
- 当数据库初始化脚本或最小表范围调整后，优先更新 `07`
- 当 `docs/data/` 文档继续增加时，再考虑拆一级分类
